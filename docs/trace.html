Agent turn traces

One column per API call (a turn); the agent's tools in that turn below the token bars. The top rows show what each turn costs: the context re-sent from the prompt cache, the new context written to it (tool results, the agent's own words) and the output. The file rows show where the agent read, searched and edited. Hover a cell for details, click a turn to list its commands; the ▸ next to "New, written to cache" and "Tool calls" opens their breakdown.

Reading the bars: the blue bar grows every turn because the whole conversation so far is re-sent with each call; the stacked bar is what the turn added: the results of the tools it called last turn (orange, estimated at 2.3 characters per token, the rate measured on these transcripts), the agent's own previous words and tool calls (green) and everything else (grey: on the first turn the task prompt, CLAUDE.md and any uncached part of the system prompt; later the per-turn reminders and instructions the CLI injects). The cost of a session is mostly the area under the blue bars, so the number of turns and what each one appends matter more than any single read. Lines attributed to files are those in tool output: a Read or cat/sed/head of the file counts as read lines, an Edit as edited lines, a grep output line naming the file as a search hit.
