# Preparation

## What changed
In `ScopingConventions.java`, the file path patterns that the task is about were moved out of the convention
list and into four named, commented constants at the top of the class. The pattern values did not change.

- `GENERATED_HTML_PAGE_PATH_PATTERN`: shared by the three generated-HTML-page rules (pkgdown, Doxygen,
  `<meta name="generator">`).
- `DOT_NET_ASSEMBLY_DOC_XML_PATH_PATTERN`: the .NET assembly `<doc>` XML rule.
- `GENERATED_JS_PATH_PATTERN`: the `// Generated by …` JavaScript rule.
- `GRADLE_JS_PATH_PATTERN`: the Gradle JavaScript build-and-deployment rule.

The `add…Conventions` methods now use these constants. Rule order and all other parameters are the same.

## Why the later change is cheaper
Before, the fix needed five edits spread over three distant parts of a 600-line file (around lines 221, 294
and 327), and the three HTML rules had the same pattern copied three times. Now it is four one-line edits in
one 12-line block next to the class header. The comments above the constants use the task's own words
(pkgdown, Doxygen, `meta name="generator"`, `.htm`, .NET assembly, `<doc>`, `MyAssembly.xml`, `app.js`,
`*-gradle.js`, `build-gradle.js`, generated / build-and-deployment scope). A grep for any of them lands
straight on that block.
