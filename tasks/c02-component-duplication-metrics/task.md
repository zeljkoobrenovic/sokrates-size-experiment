The duplication analysis publishes, for every component of every logical decomposition, three metrics in the metrics list (visible in the Metrics report and the exported data): `DUPLICATION_NUMBER_OF_DUPLICATED_LINES_<decomposition>_<component>`, `DUPLICATION_NUMBER_OF_CLEANED_LINES_<decomposition>_<component>` and `DUPLICATION_PERCENTAGE_<decomposition>_<component>`. Two of the per-component values are wrong: the cleaned-lines metric repeats the component's duplicated-line count instead of its number of lines after cleaning, and the percentage is computed as duplicated lines over duplicated lines, so it shows 100% for every component with any duplication and NaN for a component without. They should follow the same definition as the per-extension and system-wide duplication metrics: cleaned lines = the component's lines after cleaning for duplication, percentage = 100 × duplicated lines / cleaned lines (0 for a component without duplicates). For example, a component of two files with 12 cleaned lines each that share a 6-line block has 12 duplicated lines, 24 cleaned lines and 50%.

Separately, the "most frequent duplicates" list of the Duplication report (the duplicated blocks with the most occurrences, only blocks found more than twice, up to the configured top-list size) is not actually ordered by frequency: it comes out in the order in which the duplicates were found. It must list the block with the most occurrences first, then the next, in descending order of occurrences.
