Sokrates should never analyze its own output. The standard ignore rules for what Sokrates writes next to the code (the `_sokrates/` and `_sokrates_landscape/` folders, the git export files `git-*.txt` such as `git-history.txt`, and the `sokrates_*.json` conventions and configuration files) are today written into a new `config.json` by `init` only when a matching file already exists when `init` scans the tree. Usually none does yet: the history is extracted or a landscape is created after `init`, and a later `generateReports` then counts `git-history.txt`, `git-merges.txt` or the landscape files as if they were source code (for example when `txt` is among the analyzed extensions).

Make these four rules unconditional: `init` always writes them into the `ignore` list of the new configuration, also when custom scoping conventions are used, without duplicating a rule that is already there. As a safety net for configurations created before this change, `generateReports` should add any of the four rules missing from the loaded configuration in memory only, so those files are ignored during the analysis, but it must not rewrite the user's `config.json`.
