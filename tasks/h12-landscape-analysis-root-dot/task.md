When a landscape is created or updated (`updateLandscape`) from a relative analysis root such as `-analysisRoot ./acme`, the landscape's `_sokrates_landscape/config.json` stores that path verbatim as `analysisRoot`. The landscape analysis resolves a stored root that starts with "." against the folder that contains `_sokrates_landscape`, so `./acme` ends up pointing at `./acme/./acme` and the landscape silently reports 0 repositories.

Fix how the root is stored: whenever the landscape configuration lives in the default place, `<analysisRoot>/_sokrates_landscape/config.json`, the stored `analysisRoot` must be `"."` — whether the root was given as a relative or an absolute path (and also when no configuration file is given, since the default place is then used). A configuration kept anywhere else keeps the analysis root path as given. Existing landscapes that already have a broken value must heal themselves: when the landscape configuration is updated in the default layout and the existing `config.json` has an `analysisRoot` other than `"."`, it is normalized to `"."` (and saved), while everything else in the existing configuration is preserved as before.
