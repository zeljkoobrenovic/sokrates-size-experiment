Sokrates' standard scoping conventions ignore far too much: every file or folder whose name starts with a dot is dropped from the analysis ("Hidden files and folders"), so `.gitignore`, `.env`, `.editorconfig` or `.gitlab-ci.yml` vanish, and so does real source code that happens to sit under a dotted folder such as `src/.config/Foo.java`.

Change the standard conventions as follows. Plain dotfiles and anything under an arbitrary dotted folder are no longer ignored. Only the contents of version-control metadata folders — `.git`, `.svn`, `.hg` and `.bzr`, at any depth, including a path that starts directly with `.git/` — are ignored. The contents of IDE and build-tool folders — `.idea`, `.vscode`, `.vs`, `.gradle`, `.mvn`, `.settings`, `.metadata` and `.circleci`, at any depth — are not ignored but classified into the build-and-deployment scope. Also stop ignoring folders named `dependencies`, which often hold real source code. The other ignore rules (for example the `.yarn/releases` and `.yarn/plugins` rules, `node_modules`, `vendor`) stay as they are.
