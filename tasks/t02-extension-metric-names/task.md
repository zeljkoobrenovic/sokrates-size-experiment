Sokrates breaks every scope (main, test, generated, build and deployment, other) down per file extension: the analysis results written to `analysisResults.json` carry, for each scope, `linesOfCodePerExtension` and `fileCountPerExtension` entries, and the same breakdown feeds the per-extension metrics (`LINES_OF_CODE_MAIN_EXT_JAVA`, `NUMBER_OF_FILES_MAIN_EXT_JAVA`, …) and the landscape's lines-of-code-per-extension aggregation. Today each of these entries is named with a decorated label, `"  *.java"` (two spaces, a star, a dot and the lower-cased extension), which leaks verbatim into the JSON, and report code strips the decoration again with ad hoc string replacements.

Name the per-extension entries by the plain lower-cased extension instead: `"java"`, `"js"`, `"xml"`. The metric ids must stay exactly as they are. Because a landscape reads the data of repositories analyzed before this change (`"  *.java"`) as well as after it (`"java"`), its per-extension lines-of-code aggregation must merge both spellings under the one bare-extension entry — for the main scope and for the merged "other" category (build and deployment, generated, other) alike — so a mixed landscape never shows two entries for the same language, and the per-repository breakdown of a merged entry lists every repository that contributed to it. The indented `  *.ext: N files, …` lines of the textual analysis summary may keep their look. Existing tests that assert the old decorated names should be updated to the bare ones.
