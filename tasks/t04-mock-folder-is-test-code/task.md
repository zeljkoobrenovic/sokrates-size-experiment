Sokrates' default scoping conventions classify the files under a folder whose name starts with `mock` (or `__mock`) as test code — mock resources. In practice the rule misses three kinds of folder, whose files then stay in the main scope and are counted as production code: a folder named plainly `mock` (the real case: in elasticsearch, `x-pack/plugin/inference/qa/test-service-plugin/src/main/java/org/elasticsearch/xpack/inference/mock/` holds 7 files and about 2,500 lines of test-support code that no convention catches), a folder whose name carries punctuation after `mock` such as `mock.data` or `mock(old)`, and a folder whose name carries a non-ASCII character such as `mock-größe` or `mock模拟`.

Make any folder whose name starts with `mock` or `__mock` count as a mock-resources folder, whatever the rest of its name is, at any depth and also in Windows-style paths with backslashes. The match must stay within that single folder name: files under `remock/`, `demo/` or `src/main/java/`, and files merely named `mock.java` or `mockery.java`, are not test code. Every folder the rule classified as test before (`mocks/`, `__mocks__/`, `mock-data/`, `mock_data/`, `mock data/`, `mockStore/`) must keep being classified as test.
