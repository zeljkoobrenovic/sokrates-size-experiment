The landscape report's Sub-landscapes tab lists every configured sub-landscape (the `subLandscapes` links of `_sokrates_landscape/config.json`) as a table row with its logo, a link to its index page and its size and activity figures. The figures are read from each sub-landscape's `data/landscapeAnalysisResults.json`, and the report already tolerates that file being missing: the row's figures just stay empty. The logo is read from the sub-landscape's own `config.json`, and that one is not tolerated: when it does not exist or cannot be read (a stale link to a deleted folder, or a virtual-landscape child whose report has not finished generating) the whole parent landscape report aborts with a NullPointerException, and `updateLandscape` exits with 1.

Make the parent report survive a sub-landscape without a readable `config.json`: the generation completes, the row is still rendered with its link to the sub-landscape's index page and the default landscape logo (the one shown when no logo is configured), and the other rows are unaffected. Sub-landscapes that do have a config keep showing their own logo.
