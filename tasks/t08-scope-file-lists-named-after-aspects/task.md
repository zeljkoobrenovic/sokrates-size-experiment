Sokrates' report data export packages the scope file lists into `data/zips/all_files.zip` (one text entry per scope: main, test, generated, build and deployment, other), next to the loose `data/text/aspect_<name>.txt` files. When a user renames one of the scope aspects in `config.json` — for example changes the `buildAndDeployment` aspect's `name` from "build and deployment" to "buildAndDeployment", a natural edit since the JSON key reads that way — the export silently loses two files: `all_files.zip` is not written at all and, as collateral, neither is `git-history.zip`, while the run still ends normally with only a stack trace in the log. The loose text files are unaffected: they are already written under names derived from the configured aspect names.

Fix the export so that the file lists packaged into `all_files.zip` are looked up and named by the names they were written under, i.e. derived from the configured aspect names, not from fixed literals. With the default configuration nothing changes: the entries stay `aspect_main.txt`, `aspect_test.txt`, `aspect_generated.txt`, `aspect_build_and_deployment.txt`, `aspect_other.txt`, in that order. With the renamed aspect above, `all_files.zip` is written with `aspect_buildAndDeployment.txt` in the fourth place, and `git-history.zip` is written as well when a `git-history.txt` exists.
