Two defects in the Components report (the per-decomposition page with the static dependencies between logical components).

1. When a logical decomposition defines component groups (the `groups` rules with a name and a regex pattern in `config.json`), the report draws a "Group Dependencies" graph in which the dependencies between the components of two groups are merged into one link per pair of groups, with the summed file count as its label. As soon as a dependency between two groups appears in the reverse direction of one already seen (group A depends on group B, and some component of B also depends on a component of A), report generation crashes with a NullPointerException. The two directions should be merged into the one existing group link, adding the counts: for a 3-file dependency from group "Group 1" to group "Group 2" and a 2-file dependency back, the group graph has one link from "Group 1" to "Group 2" labelled 5.

2. In the "Show more details about dependencies..." table of the same report, each row shows a small bar with the share of the referring component's lines of code that depend on the referred component ("3 files, 10 LOC (12%)"). For a component whose lines of code are not counted (zero), the division yields a nonsense value: the text shows "2147483647%" (or "NaN") and the bar width overflows. Guard it: a component with no counted lines shows 0% and a minimal bar.
